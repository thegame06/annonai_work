# M1.6 — Observable Agent Execution

**The claim under test:** that an AI agent automatically consumes Annona's compiled
context while working, and that this is provable from recorded evidence rather than
narration.

**Result: proven for consumption, and the token advantage turned out to be much
smaller than M1 suggested.** That second finding is the important one.

---

## 1. Evidence that an agent consulted Annona

A real MCP session, recorded to `.annona/telemetry.jsonl` and reproduced by
`annona replay`:

```
step 1  mcp.initialize   caller=Claude Code
step 2  context          caller=Claude Code  task=TASK-0009  nodes=13  tokens=736
step 3  mcp.context      caller=Claude Code  task=TASK-0009  nodes=13  tokens=736
step 4  mcp.get_task     caller=Claude Code
step 5  mcp.search       caller=Claude Code
step 6  mcp.context      caller=Claude Code  ok=false
```

The caller names itself in the MCP handshake; every subsequent record carries that
attribution. Failures are recorded as failures. Nothing here is narrated — it is read
back from disk by a later process.

| Capability | Status |
|---|---|
| Session grouping | Every record carries a session id, derived, never configured |
| Caller attribution | From the MCP `clientInfo` handshake |
| Replay after exit | `annona replay` reads the file; no live state |
| Field discipline | 16 permitted fields, enforced by a test |

## 2. The finding that changes the product story

`annona bench agent` runs two arms over 10 golden tasks. Arm A simulates a *competent*
repo-only agent: it greps for the task id, opens the hits, follows every reference it
finds, and opens those. Arm B is Annona's compiled context.

| | Repo-only (grep) | Annona |
|---|---|---|
| Mean tokens | 1,193 | 655 |
| **Mean reduction** | | **37.6%** |
| Worst case | | **−43.7%** (TASK-0009: 638 vs 444) |
| Files read | 15.4 | — |
| Searches | 4.4 | — |
| COMPLETE verdicts | — | 10/10 |

**M1 reported 92.6%. That was against a strawman** — an agent that dumps every file
into the prompt. Against an agent that greps competently the advantage is 37.6%, and
on one task in ten Annona costs *more* than grepping.

This is not a reason to stop. It is a reason to stop leading with the token number.
The defensible claims are:

- **Determinism.** Grep results depend on naming, file layout and the agent's search
  strategy. Annona's context is identical every run, and `annona context diff` works.
- **A completeness verdict.** Grep cannot tell you it missed the governing ADR.
  Annona returns `COMPLETE` or names what is absent — 10/10 COMPLETE here.
- **Flat cost at scale.** The repo-only arm grows with the corpus (more files mention
  the same ids); Annona's context is a function of the task. Measured in M1: 161
  tokens at 110 entities and at 4,200.

The 92.6% figure remains true for its baseline and should be labelled as such: it is
the *undisciplined* case, not the competitive one.

## 3. Drift detection and cheap completion

Dogfooding in M1.5 measured 17 manual edits to resync one milestone. `annona done`
replaces them:

```
annona done TASK-0011 --touches=CMP-0004,CMP-0005
  updated annona/features/FEAT-0005/TASK-0011.yaml
  recompiled: ok
  review TEST-0008: still marked pending and verifies what this task implemented
```

All six M1.6 tasks were closed this way. Manual edits this milestone: **0**.

`doctor` gained three drift checks that report evidence rather than suspicion:

| Check | Evidence it requires |
|---|---|
| `stale-status` | task still open, yet every requirement it implements is verified by a passing test |
| `missing-touches` | task done, no touched component recorded |
| `dead-term` | glossary term named nowhere else in the knowledge |

After closing the milestone properly, the knowledge base reports **1 finding** on 64
entities: a component no task has touched, which is true.

## 4. Metrics, computed not calculated

`annona metrics` reads only telemetry: sessions, agent calls, callers, tasks
completed, drift scans, median and mean context latency, cache hit ratio, knowledge
coverage, most requested tasks, failures. No number in this document was computed by
hand.

## 5. What is still not proven

**The model arm did not run.** `annona bench agent --runner=<cmd>` shells out to any
agent CLI, and Arm A/Arm B prompts are written to disk ready for it. This environment
has no model API key and no network route to one, so **iterations, elapsed time and
completion quality are unmeasured**. The harness reports `modelArmRun: false` and says
so in its own output rather than estimating.

Running it requires one command with a key present. Until then:

- Token and search costs: **measured**
- Whether an agent *succeeds more often* with Annona context: **unmeasured**

That remains the largest open question in the product, and it is now the only thing
standing between the current evidence and a commercial claim.

**Second honest limit:** Arm A is a *lower bound*. A real agent also opens files that
turn out to be irrelevant, so repo-only costs are higher in practice than reported —
which makes 37.6% conservative. But it is simulated, not observed.

## 6. Friction recorded (3 new, 11 total)

1. **`done` asserted test outcomes it could not know** — contradicting REQ-0013 in the
   same milestone that declared it. Fixed: it reports, never asserts.
2. **The token claim collapsed under a fair baseline** — reframes over-retrieval from
   cosmetic to decisive.
3. **Session ids are per-process, so one work stretch produced 8 sessions.** ADR-0005
   chose process-derived to avoid depending on caller discipline; dogfooding shows the
   result is unusable for replay. This is the first ADR that usage has contradicted,
   and it should be revisited with the evidence attached.

## 7. Backlog, reordered by what the evidence now says

1. **Run the model arm.** Everything else is secondary; this is the missing proof.
2. **Fix over-retrieval** (friction 4, now 10). It decides whether Annona beats grep
   on small tasks. Bound `depends_on` and `constrains` expansion, measure with
   `bench agent`.
3. **Revisit ADR-0005** on session identity (friction 11).
4. **Dedupe summary/body overlap** (friction 3) — cheap, and every token counts now
   that the margin is 37.6% rather than 92.6%.
